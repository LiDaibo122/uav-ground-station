# Qwen 流式对话与生成预算

轻量入口为 http://127.0.0.1:11843/chat.html ，原三维页面也使用同一流式接口。刷新页面即可加载新前端；Python 后端须在重启后加载代码。启动和 Windows QGC 操作见 [QGC 流程](QGC_WORKFLOW.md)。

## 页面反馈

- 模型准备、推理期间显示阶段、等待时间和内部生成字符数，不展示内部思考原文。
- 模型开始生成正文后逐段显示，生成中的正文标记为临时内容；最终回答和实际工具回执返回后替换它。
- 工具开始与返回时立即显示进度，完整参数、结果和执行回执仍可展开查看。收到回执不表示飞机已经离地、抵达或降落，实际状态以遥测和 QGC 为准。
- 生成额度耗尽或连接中断时保留已取得的工具结果；未完成正文单独标注，未完成的工具调用不会进入执行器。
- 网络中断后不自动重发。关闭页面也不会撤销已经执行的操作，应核对实际状态后再决定下一条指令。

## 仍然存在的限制

流式输出让生成过程可见，不会扩大模型能力或消除所有超时。首次加载模型仍可能等待，本机冷加载探测约23秒；正文也要等模型结束当前推理后才出现。

当前输入窗口为16384 token，每次推理预留4096 token生成空间和1024 token安全余量；历史与工具结果按预算压缩。每个模型步骤最多生成4096 token。连续只思考且没有正文或工具调用达到18秒时中止当前生成；单步生成时间预算60秒，整轮在开始下一步前检查90秒预算。读取连接的无数据超时为30秒。这些是有界等待策略，不是自动完成缺失功能的办法；工具执行本身不会被90秒检查强行打断。

模型仍使用原生工具调用和思考模式。同一用户回合内的必要模型状态传入后续工具回合，不作为历史不断累积。底层持续遥测与网页轮询不会主动调用模型，每次工具查询只提供一次快照。

相对编队位移、指定圈数盘旋、盘旋结束自动返航的完整任务序列尚未实现。对于“全部往北飞100米，绕行一周返航”，目前应说明能力缺项，不能声称已执行整段任务。

## 接口与兼容

`POST /api/chat/stream` 接收与 `/api/chat` 相同的 JSON，返回逐行 JSON 事件：`start`、`model_start`、`model_progress`、`text_delta`、`tool_start`、`tool_result`、`result` 或 `error`。最后的 `result` 是完整持久化结果；前面的正文是临时内容。

保留 `/api/chat` JSON 接口。浏览器只有在流式路由返回404或405、尚未执行请求时才回退旧接口；流已开始后不会回退重试。

已在三架飞机均落地、未解锁且模型空闲时更新运行服务，保留原 QGC 桥；更新后集群处于等待任务状态，检查记录为 `reports/stream-deployment.json`。实际部署接口的只读提问探测，首个事件0.002秒、首段正文2.83秒、最终结果3.32秒，无工具调用，记录为 `reports/stream-live-verification.json`。这条简单提问的时延不能代表规划任务时延。

单元测试覆盖中断、缺少结束标记、长度上限、思考与生成时间预算、已执行一次后超时保留回执，以及 HTTP 在最终结果前刷新正文。浏览器隔离测试覆盖逐段渲染、中文分片、截断保留、断线保留及不自动重发，报告为 `reports/chat-stream-browser.json`。
