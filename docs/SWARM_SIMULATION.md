# 固定翼集群：第一阶段实现与复现

当前默认启动流程已升级为等待 Qwen 对话任务，见 [对话调度说明](QWEN_DISPATCH.md)。本页的六点实验是保留的回归验证，运行时需要加 `--fixture`。

本阶段实际运行的是 **CBBA 多任务拍卖 → MAVLink 任务上传 → 3 个 PX4 固定翼飞控 → Gazebo 气动仿真 → 遥测到点验证**。网页接收真实 SITL 遥测，并显示各机任务归属与到点记录。飞机位置没有用前端动画代替。

## 获取的源码

| 源码 | 作用 | 许可 | 本工程使用情况 |
|---|---|---|---|
| [CBBA-Python](https://github.com/zehuilu/CBBA-Python) | 一架机连续领取多个任务，通过交换赢家/出价消除归属冲突 | MIT | 保留上游共识与 bundle 实现，独立适配固定翼评分和数据类型 |
| [SSlap](https://github.com/OllieBoyne/sslap) | 基础拍卖，求一对一线性匹配 | MIT | 编译并用于最优匹配对照，不承担本次多航点调度 |

精确提交号、原始许可证、论文和开发环境见 [SOURCES.json](../third_party/SOURCES.json)。SSlap 的 `np.float` 改为 `np.float64` 以兼容 NumPy 1.24，补丁单独保留。没有把两套算法混称为一种算法。论文对照仓库的失效链接也记录在清单中。

CBBA 的 `quad/car` 硬编码没有用于描述实际机型。本地子类使用 `fixedwing/inspection` 类型，重写领域评分；上游 `communicate/bundle/solve` 保持原样。实际 MAVLink 心跳必须报告 PX4 与固定翼机型才进入验证。

出价采用 `任务价值 × exp(-0.003 × 预计到达时间)`，高/常规/低优先级对应 2000/1000/500。25% 以下电量及不可用飞机不参加拍卖；每架机容量默认 2。到达时间先按平面直线距离与标称速度估算，尚未计入起飞爬升、转弯半径和风，不能据此保证紧迫截止时间。任务分配不提供完整的航迹可飞性保证。

## 运行

本机已具备 PX4 v1.13.3、Gazebo Classic、`plane` 模型及插件，不需要重新编译 PX4。只启动无界面的 `gzserver`，浏览器显示状态。

```bash
cd /home/ldb/ground_station
python3 -m packages.swarm_sim.verify_auction
python3 -m packages.swarm_sim.demo --fixture --hold
```

打开 **http://127.0.0.1:11843/?mode=live&swarm=1**。`--hold` 在全部任务通过后保持盘旋和遥测，按 Ctrl+C 停止本次仿真；复用原来已运行的地面端服务时不会将其关闭。不加 `--hold` 时，完成或失败后自动停止自己创建的 PX4/Gazebo 进程。

验证报告和过程记录位于 `runs/swarm/`。一轮试验后想从全新参数重跑，可将已停止的 `runs/swarm/` 改名归档，再运行上述命令。直接重新运行会复用上次的 SITL 参数存储；飞行模式、解锁和任务仍会重新发送。

独立控制入口：

```bash
python3 -m packages.swarm_sim.sitl start
python3 -m packages.swarm_sim.verify_flight --timeout 600
python3 -m packages.swarm_sim.sitl stop
python3 -m packages.swarm_sim.export_report
```

启动器只管理本次运行记录的进程组，不调用 `pkill px4` 或关闭其他仿真。默认用 Gazebo master 11359；当前三架机分别使用 MAVLink 14541/14542/14543、飞控实例 1/2/3、系统 ID 2/3/4，业务编号仍为 FW-01/02/03。旧六点报告来自此前的实例 0/1/2。MAVLink 仅绑定本机。此工具固定用于本机 SITL，没有串口或远程真机地址参数。

其他开发机先安装与其 Python 版本相适配的依赖，并准备相同 PX4/Gazebo 构建。本机可参考 `requirements-simulation.txt`。源码复现入口如下，精确锁定到清单中的提交：

```bash
python3 scripts/fetch_auction_sources.py --build-baseline
python3 -m packages.swarm_sim.demo --fixture --px4 /path/to/PX4-Autopilot --hold
```

## 验证判据

算法层做了 120 组 3/5/10/20 阶整数矩阵的拍卖与 SciPy 最优匹配对照，以及 60 组随机 CBBA 几何场景。另检验任务归属唯一、容量上限、赢家视图一致、不可用机排除、低电量排除、容量不足显式报告和同距离高优先级获胜。基础一对一拍卖与最优解相同，**不代表 CBBA 的多任务路径全局最优**。

飞行场景包含 6 个巡检点，位于仿真原点以东 900/1600 米和以北 0/350/700 米的三条航带。由实时 GPS 初始位置输入 CBBA，随后按算法输出生成各机任务，包含跑道起飞、巡检航点、结束盘旋以及合法降落备选航段。

每个巡检点必须同时满足以下条件才计入完成：

- 所属飞机的实时 GPS 距离目标不超过 85 米；
- 相对起飞点高度超过 50 米，地速超过 10 米/秒；
- PX4 已上报该航点通过，或任务当前序号已推进到后一个航点。

位置消息超过 2 秒不进入判断或刷新网页。任务上传需要所有序号的请求和 `MISSION_ACK`，解锁、切换模式需要飞控回执。没有强制解锁或关闭飞控任务校验。固定翼要求的降落航段保留在无限盘旋之后，本阶段不验证自动着陆。

实际分配、每点到达距离/高度/速度、遥测 CSV、轨迹图和浏览器截图保存在 `reports/`。离线“飞机不可用”与低电量重拍卖通过，但没有把它们称为空中故障接管测试。

## 边界与后续工作

- 此次 CBBA 共识在地面端单进程同步模拟全连接邻居；尚未实现机间分布式竞价消息传输。这适合当前地面集中调度的第一轮验证。
- Gazebo 是平地物理世界，原点对齐龙池坐标。网页的山地地形没有进入仿真碰撞体、相机或高度规划，不能用此结果宣称山区飞行净空已验证。
- 采用不同巡航高度便于观察。尚无 VO、动态避碰、地形规避、固定翼 Dubins 航迹或空域冲突检测，起飞与爬升过程也未作间隔保证。
- `observations.py` 将实际仿真 GPS/速度/高度等确定性地转成带时间和来源的中文文本。没有实现世界模型，也没有捏造火情、积水或滑坡识别。
- 本页的 6 个地理任务来自明确的回归场景；当前主流程已支持 Qwen 对话中的明确坐标或已有地图区域，经校验后按实时状态拍卖下发。任意地名解析和完整覆盖航线仍待实现。
- 后续按顺序接任务区域解析与任务库、动态重规划、固定翼航迹约束和避碰、仿真图像/灾害事件文本，再做 ROS 接口与 310P 适配。

当前模块均与 ROS、CANN 和前端分开：`auction.py` 做分配，`mavlink_io.py` 做仿真链路，`observations.py` 做文本转换，`sitl.py` 管理仿真进程。迁移 310P 时可保留领域数据契约；算法运行 CPU，Qwen 推理另接昇腾可用服务。当前 x86_64 的 SSlap `.so` 不能复制到 ARM 使用，需要在目标架构重编译；PX4/Gazebo 开发仿真无需随地面业务一起部署到 310P。本轮未验证昇腾推理。
